*2026年10月31日時点で確認した内容です。裁判や政府の判断で状況が動くテーマなので、最新の情報は[Appleの英国向けサポート記事](https://support.apple.com/ja-jp/122234)で確認してください。この記事は技術的な状況の解説であり、法的な助言ではありません。*

「高度なデータ保護」は、iCloudデータの大部分をエンドツーエンドで暗号化する、Appleのオプション設定です。世界のほとんどの地域では1分でオンにできますが、イギリスではできません。「高度なデータ保護 イギリス」で検索すると、古い見出しと噂が入り混じっています。ここでは、確認できている事実、まだ決着していないこと、そして今日から写真のためにできることを整理します。

## イギリスで何が起きたのか

要点はこうです。イギリス政府は監視に関する法律を使って、暗号化されたiCloudデータへのアクセス手段を要求しました。Appleはその仕組みを作る代わりに、機能そのものを引き上げました。

- **2025年1月：** 英内務省がAppleに、調査権限法（Investigatory Powers Act 2016）に基づく**技術的能力通知**（TCN）を出したと報じられました。ワシントン・ポストが最初に伝えた内容によると、エンドツーエンドで暗号化されたiCloudのデータにアクセスできる能力を求めるもので、対象はイギリス国内に限らず世界中のユーザーだったとされます。法律上、企業はこうした通知の存在を認めることを禁じられているため、Appleも政府も公式には認めていません。
- **2025年2月21日：** Appleはイギリスの新規ユーザーへの「高度なデータ保護」の提供を停止しました。声明でAppleは「深く失望している」と述べ、自社の製品やサービスに「バックドアやマスターキーを作ったことはなく、今後も作らない」としています。
- **2025年春：** Appleは、英国の監視権限に関する申し立てを扱う**調査権限審判所**（Investigatory Powers Tribunal）で命令に異議を申し立てました。2025年4月、審判所は事件の基本的な事実まで秘密にしたいという政府の要求を退けました。
- **2025年8月：** 米国の国家情報長官トゥルシー・ギャバード氏が、イギリスは要求を取り下げることに同意したと発表しました。英内務省は肯定も否定もしていません。
- **2025年10月：** フィナンシャル・タイムズが、内務省がイギリスのユーザーのデータに限定した、新しい範囲の狭い通知を出したと報じました。AppleはADPを再開しませんでした。
- **2026年：** Appleの最初の申し立ては、元の通知が差し替えられたことで終了したと報じられ、Appleは新しい通知に対して改めて異議を申し立てました。<!-- TODO verify --> 2026年9月17日の審理では、政府が通知の存在を「肯定も否定もしない」姿勢を続けられるかが争われました。Privacy InternationalとLibertyによる別の申し立ては2026年12月に審理予定で、ロイターはApple自身の本審理は2027年より前には開かれない見通しだと伝えています。

2026年10月下旬の時点で、審判所はどちらの事件についても中身の判断を示しておらず、Appleもイギリスで「高度なデータ保護」を再開していません。

## イギリスでADPは再開された？

されていません。Appleのサポート記事「Appleは英国の新規ユーザへの高度なデータ保護の提供を終了します」は、2026年10月末の時点でも内容が変わらず公開されています。記事には、イギリス以外の世界中では引き続き利用できると書かれています。イギリスのApple Accountで「設定」›［ユーザ名］›「iCloud」を開いて**高度なデータ保護**を探しても、オンにはできません。

「イギリスでADPが復活した」とする記事には注意してください。2025年8月の発表は、アメリカ人のデータについての要求をイギリスが取り下げたという話で、Appleがイギリスのユーザー向けに機能を戻したという話ではありません。

## すでにADPをオンにしていた人は？

ここは公開情報がもっとも少ない部分です。ADPはエンドツーエンドで暗号化されているため、Appleはユーザーに代わってオフにすることはできないとしています。サポート記事には、すでにADPを有効にしているイギリスのユーザーは「一定の期間内にこの機能をご自身で無効にしていただいた上で」iCloudアカウントを使い続けることになり、「近日中に追加ガイダンスをご案内します」と書かれています。

2026年10月時点でも記事の文言は同じで、期限は示されていません。<!-- TODO verify --> 該当する人は、iPhoneにAppleからの案内が表示されたら内容をよく読んで従い、設定を変える前に大切なデータのコピーを手元に作っておきましょう。

## イギリスでも今もエンドツーエンドで暗号化されるもの

ADPの停止は、Appleが初期設定でエンドツーエンド暗号化しているカテゴリには影響しません。AppleのiCloudセキュリティの概要によると、次の15のカテゴリはイギリスを含むすべてのユーザーでエンドツーエンド暗号化のままです。

- パスワードとキーチェーン
- ヘルスケアのデータとジャーナルのデータ
- ホームのデータ
- iCloudのメッセージ（iCloudバックアップがオフの場合のみ。後述）
- 支払い情報とApple Cardの取引
- マップ（ピン、ガイド、検索履歴）
- Safariの履歴、タブグループ、iCloudタブ
- スクリーンタイム、Siriの情報、Wi-Fiのパスワード、QuickTypeキーボードの学習語彙、Bluetoothの鍵、ミー文字

iMessageとFaceTimeも、世界中で通信がエンドツーエンドで暗号化されたままです。

ひとつ大きな落とし穴があります。**iCloudバックアップがオンだと、バックアップにiCloudのメッセージの鍵のコピーが含まれます。** ADPがなければそのバックアップは標準のデータ保護なので、メッセージのプライバシーはバックアップと同じレベルにとどまります。

## ADPなしではエンドツーエンド暗号化されないもの

ADPが守るはずだった10のカテゴリは、イギリスの新規ユーザーでは標準のデータ保護のままです。

| カテゴリ | ADPなしのイギリスのユーザー |
| --- | --- |
| 写真（「非表示」と「最近削除した項目」を含む） | 暗号化、鍵はAppleが保持 |
| iCloudバックアップ（デバイスとメッセージのバックアップ） | 暗号化、鍵はAppleが保持 |
| iCloud Drive | 暗号化、鍵はAppleが保持 |
| メモ、リマインダー、ボイスメモ | 暗号化、鍵はAppleが保持 |
| Safariのブックマーク、ショートカット、Walletのパス、フリーボード | 暗号化、鍵はAppleが保持 |

「鍵はAppleが保持」といっても、データが平文で置かれているわけではありません。通信中もAppleのサーバー上でも暗号化されています。違いは誰が復号できるかです。標準のデータ保護ではAppleが復号できます。だからアカウントの復旧ができる一方で、法的な要請によってデータに届いてしまいます。メール、連絡先、カレンダーは、ADPの有無にかかわらず、どの地域でもエンドツーエンド暗号化されません。

## イギリスのユーザーが写真をエンドツーエンドでないiCloudに置かない方法

ADPは使えなくても、そもそも何をiCloudに送るかは自分で決められます。手間の少ない順に並べます。

1. **iPhoneでiCloud写真をオフにする。** 「設定」›［ユーザ名］›「iCloud」›「写真」で**このiPhoneを同期**をオフにします（古いバージョンでは**iCloud写真**）。新しい写真はデバイスに残ります。すべてのデバイスでiCloud写真の利用をやめると、iCloud上の写真は30日後に削除されるとAppleが案内しているので、先にコピーをダウンロードしておきましょう。
2. **写真をiCloudバックアップから外す。** iCloud写真がオフでiCloudバックアップがオンだと、ライブラリはバックアップに含まれます。「設定」›［ユーザ名］›「iCloud」›「iCloudバックアップ」でバックアップをオフにするか、お使いのiOSで選べる場合は写真をバックアップから外します。両者の関係は[非表示の写真はiCloudに保存されるのか](id:are-hidden-photos-saved-to-icloud)で詳しく説明しています。
3. **代わりにコンピュータへ暗号化してバックアップする。** 自分のコンピュータのFinderや「Appleデバイス」アプリで作るバックアップはiCloudに送られません。**ローカルのバックアップを暗号化**にチェックを入れ、自分で決めたパスワードで保護しましょう。
4. **機密性の高いものに共有アルバムを使わない。** 共有アルバムは、ADPが使える地域でもエンドツーエンドで暗号化されません。
5. **Webからの入口を閉じる。** [WebでのiCloudデータへのアクセス](id:icloud-access-data-on-web)をオフにしても暗号化は強くなりませんが、ブラウザのiCloud.comでデータが表示されなくなります。
6. **特にプライベートなファイルはデバイス上の暗号化保管庫に入れる。**

## デバイス上の保管庫の位置づけ

ADPがない状況で、写真をAppleのサーバーから遠ざけるもっとも確実な方法は、そもそもサーバーに置かないことです。デバイス上の保管庫は、iPhoneの中でファイルを暗号化し、鍵がiPhoneの外に出ることはありません。

Velcryptはこの仕組みです。読み込んだ写真、動画、書類はAES-256-GCMで暗号化され、鍵はあなたが描く5×5のパターンから導出されます（[暗号化の仕組み](id:encryption)）。アカウントもサーバーもなく、保管庫の中身はiCloudやコンピュータのバックアップから除外されます（[デバイス上で完結、アカウント不要](id:offline-no-account)）。パターンごとに別の保管庫が開くので、アプリを開けるよう迫られたときのためのダミー保管庫も用意できます。

読み込んだあとは、写真ライブラリと「最近削除した項目」から元の写真を削除しないと、同期され続けます。詳しくは[読み込んだ後に元の写真を削除する方法](id:delete-original-photos-after-import)を参照してください。万一に備えたいなら、Velcryptは自分で決めたバックアップパスワードで保護された暗号化バックアップファイルを作れます。このファイルはアプリを出る前に暗号化されるので、標準のデータ保護のiCloud Driveに保存しても、Appleが保管するのは暗号文だけです。

トレードオフはADPと同じで、さらに厳格です。パターンやバックアップパスワードを忘れると、私たちを含め誰も保管庫を復旧できません。2つの考え方をさらに比べたいなら、[iCloudの「高度なデータ保護」とは](id:icloud-advanced-data-protection-explained)を読んでみてください。
